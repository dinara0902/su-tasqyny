## 1. Карта форматы

Мысал карта: [`data/village.json`](../data/village.json). Ауыл 24×16 ұяшықтан тұрады.

| Белгі | Мағынасы | Өтуге бола ма |
|---|---|---|
| `#` | ғимарат немесе кедергі | жоқ |
| `.` | жол | иә |
| `~` | өзен, су | жоқ |
| `=` | көпір | иә, бірақ су басу қаупі жоғары |
| `H` | тұрғын үй | иә (бастапқы нүкте) |
| `S` | эвакуация пункті | иә (мақсат) |

**Координаттар:** `x` — баған (солдан оңға, 0-ден), `y` — жол (жоғарыдан төменге, 0-ден). Ұяшық белгісі: `grid[y][x]`.

**Көршілер:** тек 4 бағыт (жоғары, төмен, солға, оңға). Диагональ жоқ.

**Өзге өрістер:**
- `priors` — Байес үшін алғашқы ықтималдықтар: әдеттегі жол `0.05`, суға жақын жол `0.3`, көпір `0.6`.
- `shelters` — пункттер: `id`, `name`, `x`, `y`, `capacity` (орын саны), `hasMedical` (медициналық көмек бар ма).
- `families` — отбасылар: `id`, `name`, `house {x, y}`, `size` (адам саны), `needsMedical`, `elderly` (қарт адамдар саны).
- `sampleReports` — тексеруге арналған мысал хабарламалар.

Мысал картада өзен ауылды екіге бөледі, екі жағы тек көпір арқылы жалғасады. Көпірді су басса, батыс жағындағы отбасылар тек №2 пунктке (Мәдениет үйі) бара алады. Байестің A\* пен CSP-ге әсері дәл осы жерде көрінеді.

## 2. Модульдердің жалпы ережесі

Әр алгоритм файлы әрі браузерде, әрі Node.js-те (тесттерде) жұмыс істеуі керек. Ол үшін файлдар осы үлгімен жазылған:

```js
(function (root, factory) {
  if (typeof module === 'object' && module.exports) module.exports = factory();
  else root.Search = factory();          // браузерде: window.Search
})(typeof self !== 'undefined' ? self : this, function () {
  // ... алгоритм коды ...
  return { aStar, bfs };
});
```

**Маңызды:** алгоритм файлдарында `document`, `window`, `alert` сияқты браузер нәрселерін қолданбаңыз. Олар тек `src/ui/app.js`-те болады.

## 3. Байес модулі (6-апта)

**Файл:** `src/algorithms/bayes.js` · **Жауапты:** Жарқын Динара

**Не шешеді:** адамдар «бұл жолды су басты» немесе «бұл жол құрғақ» деп хабарлайды, бірақ кейде қателеседі. Модуль әр жол ұяшығы үшін P(су басты) ықтималдығын есептейді.

**Модель:**
- Әр ұяшықта жасырын күй бар: `F` — су басты, `¬F` — құрғақ.
- Алғашқы ықтималдық P(F) картаның `priors` өрісінен алынады.
- Хабарламаның сенімділігі `r` (мысалы, `0.8`):
  - P(хабар «су басты» | F) = r
  - P(хабар «су басты» | ¬F) = 1 − r

**Байес ережесі** («су басты» деген хабар келгенде):

```
                 r · P(F)
P(F | хабар) = ─────────────────────────────
               r · P(F) + (1 − r) · (1 − P(F))
```

«Құрғақ» деген хабар келгенде `r` мен `1 − r` орындарын ауыстырасыз. Хабарламалар бір-бірінен тәуелсіз деп алынады, сондықтан оларды бір-бірлеп қолданасыз: бір хабардан кейінгі нәтиже келесі хабар үшін P(F) болады.

**Функциялар:**

| Функция | Кіріс | Шығыс |
|---|---|---|
| `priorFor(map, x, y)` | карта, ұяшық | осы ұяшықтың алғашқы P(F) мәні. Көпір → `bridge`, `~` көрші → `nearWater`, әйтпесе `default` |
| `update(p, says, r)` | алдыңғы ықтималдық, `'flooded'` не `'dry'`, сенімділік | жаңа ықтималдық |
| `applyReports(map, reports, r)` | карта, хабарламалар тізімі, сенімділік | `Map`: `"x,y"` → P(F) барлық өтуге болатын ұяшық үшін, және `steps`: әр хабардан кейінгі өзгеріс («Қалай ойлады?» үшін) |

**Мысал (қолмен тексеруге болады):** көпір P(F) = 0.6, r = 0.8, «су басты» деген бір хабар:
P = 0.8·0.6 / (0.8·0.6 + 0.2·0.4) = 0.48 / 0.56 ≈ **0.857**.

## 4. A\* және BFS (2-апта)

**Файл:** `src/algorithms/search.js` · **Жауапты:** Марат Нәрлі

**Не шешеді:** үйден ең жақын (немесе таңдалған) эвакуация пунктіне дейінгі ең қауіпсіз жолды табады.

**Қадам құны:**

```
құн(ұяшық) = 1 + penalty · P(F)
```

- `P(F)` Байес модулінен келеді (жоқ болса, 0).
- `P(F) > threshold` болса, ұяшық **жабық** деп саналады (өтуге болмайды).
- Әдепкі мәндер: `penalty = 10`, `threshold = 0.7`.

**Эвристика:** Манхэттен қашықтығы `h = |x − x₂| + |y − y₂|`. Бір қадам құны кемінде 1 болғандықтан, h нақты құннан ешқашан аспайды (admissible), сондықтан A\* ең арзан жолды табады. Бірнеше мақсат болса: h = барлық пунктке дейінгі ең кіші Манхэттен қашықтығы.

**A\* қадамдары:**
1. `open` тізіміне бастапқы ұяшықты f = g + h мәнімен қосу (`g` — осы уақытқа дейінгі құн).
2. `open`-нан f ең кіші ұяшықты алу. Ол мақсат болса, жолды `cameFrom` арқылы қалпына келтіріп, тоқтау.
3. Әр көршіге: жаңа g = g(ағымдағы) + құн(көрші). Бұрынғыдан аз болса, жаңартып, `open`-ға қосу.
4. Ұяшықтарды зерттеу ретін `order` тізіміне жазу («Қалай ойлады?» үшін).

**BFS:** құнды ескермей, қадам саны бойынша ең қысқа жолды табады. Салыстыру үшін керек: P(F) = 0 болғанда екеуінің жол ұзындығы бірдей болуы керек, бірақ A\* аз ұяшық зерттейді.

**Функциялар:**

| Функция | Кіріс | Шығыс |
|---|---|---|
| `aStar(map, start, goals, options)` | карта, `{x, y}`, мақсаттар тізімі `[{x, y}]`, `{floodProb, penalty, threshold}` | `{ found, path: [{x,y}], cost, goal, expanded, order }` |
| `bfs(map, start, goals, options)` | дәл солай | дәл солай (`cost` = қадам саны) |

Жол табылмаса: `{ found: false, path: [], cost: Infinity, expanded, order }`. Қате шығармайды.

## 5. CSP модулі (3-апта)

**Файл:** `src/algorithms/csp.js` · **Жауапты:** Нұрдаулет Шұғыла

**Не шешеді:** әр отбасын бір эвакуация пунктіне бөледі.

**CSP құрылымы:**
- **Айнымалылар:** отбасылар (`F1`, `F2`, …). Отбасы бөлінбейді: бір айнымалы — бүкіл отбасы.
- **Домен:** әр отбасы бара алатын пункттер.
- **Шектеулер:**
  1. **Сыйымдылық:** бір пункттегі адамдар саны (`size` қосындысы) `capacity`-ден аспайды.
  2. **Медицина:** `needsMedical = true` болса, тек `hasMedical = true` пункт.
  3. **Қашықтық:** A\* тапқан жол құны `maxCost`-тан аспайды; жол мүлдем табылмаса, ол пункт доменнен шығады.

**Алгоритм:**
1. **Бастапқы домендер:** әр отбасы үшін 2- және 3-шектеуге сай келетін пункттер.
2. **Backtracking:** отбасыны таңдап, оған пункт беріп, рекурсиямен жалғастыру. Тұйыққа тірелсе, артқа қайту (`backtracks += 1`).
3. **MRV (Minimum Remaining Values):** келесіге домені ең кіші отбасыны таңдау. Тең болса, үлкен отбасы бірінші.
4. **Мәндер реті:** алдымен жақын пункт (A\* құны аз).
5. **Forward Checking:** пункт бергеннен кейін қалған отбасылардың доменінен өзі сыймайтын пункттерді алып тастау. Біреудің домені бос қалса, бірден артқа қайту.

**Функция:**

| Функция | Кіріс | Шығыс |
|---|---|---|
| `solve(families, shelters, distances, options)` | отбасылар, пункттер, `distances[familyId][shelterId]` (A\* құны не `Infinity`), `{maxCost, useMRV, useForwardChecking}` | `{ ok, assignment: {F1: 'S2', …}, load: {S1: 10, …}, backtracks, nodes, steps }` |

Шешім жоқ болса: `{ ok: false, reason: '…', … }`. Мысалы, «орын жетпейді: 40 адам, 37 орын».

**Салыстыру:** `useMRV: false` пен `useMRV: true` кезіндегі `backtracks` санын benchmark-та көрсету.

## 6. Интерфейс

**Файлдар:** `index.html`, `src/ui/app.js`, `src/ui/style.css` · **Жауапты:** Нұрдаулет Шұғыла (дизайн), бәрі бірге (қосу)

**Негізгі экран:**
- Сол жақта: Canvas-та карта. Үйлер, пункттер, су, көпір көрсетіледі. Ұяшық түсі P(F)-ке байланысты: ақшыл көктен қою көкке дейін.
- Оң жақта: басқару панелі.

**Әрекеттер:**
1. Ұяшықты басу → «Су басты» / «Құрғақ» хабарламасы. Байес қайта есептейді.
2. Үйді басу → A\* сол үйден маршрут салады.
3. «Барлығын бөлу» батырмасы → CSP іске қосылады, нәтиже кесте және картадағы түстер арқылы көрсетіледі.
4. Параметрлер: хабар сенімділігі `r`, `threshold`, пункттердің сыйымдылығы.
5. «Қалай ойлады?» режимі:
   - A\*: зерттелген ұяшықтарды ретімен боятып көрсету, A\* мен BFS санын салыстыру.
   - Байес: әр хабардан кейін P(F) қалай өзгергенін көрсету.
   - CSP: қай отбасыға қай пункт берілгені, қай жерде артқа қайтқаны.

**Міндетті ескерту** беттің жоғарғы жағында: «Бұл оқу прототипі. Төтенше жағдайда 112 нөміріне хабарласыңыз.»

## Тесттер

Әр модульге кемінде 5 тест. Тест файлдарында бос үлгілер (`test.todo`) дайын тұр: оларды нақты тестке айналдырыңыз.

**Байес** (`tests/bayes.test.js`):
1. P = 0.6, r = 0.8, «су басты» → ≈ 0.857.
2. «Су басты», содан кейін «құрғақ» (бір r) → P бастапқы мәнге қайтады.
3. r = 0.5 болса, хабар P-ні өзгертпейді.
4. Бірдей бес хабар → P 1-ге жақындайды, бірақ 1-ден аспайды.
5. Қате енгізу: r = 1.5 немесе `says = 'abc'` → түсінікті қате.

**A\* және BFS** (`tests/search.test.js`):
1. Бос картада A\* мен BFS жол ұзындығы бірдей.
2. A\* BFS-тен аз немесе тең ұяшық зерттейді.
3. Жабық ұяшық (P > threshold) арқылы жол өтпейді.
4. Мақсатқа жол жоқ → `found: false`, қате шықпайды.
5. Бастапқы нүкте мақсаттың өзі → жол ұзындығы 1, құн 0.
6. Қате енгізу: картадан тыс координат → түсінікті қате.

**CSP** (`tests/csp.test.js`):
1. Мысал картада барлық отбасы орналасады, сыйымдылық бұзылмайды.
2. `needsMedical` отбасы тек медициналық пунктке түседі.
3. Орын жетпесе → `ok: false` және себебі жазылған.
4. MRV-мен backtrack саны MRV-сызбен салыстырғанда көп емес.
5. Пунктке жол жоқ болса (`Infinity`), отбасы оған берілмейді.
6. Қате енгізу: теріс сыйымдылық, `size = 0` → түсінікті қате.

**Бірге жұмыс** (`tests/integration.test.js`):
1. Көпірге «су басты» деген 3 хабар → көпір жабылады → батыс жағындағы отбасылар тек S2-ге бара алады → CSP соған сай бөледі.

## 8. Қате енгізуді өңдеу

- Алгоритм функциялары қате кіріс келсе, түсінікті хабармен `Error` шығарады (мысалы, `'Сенімділік 0 мен 1 аралығында болуы керек'`).
- Интерфейс бұл қатені ұстап (`try/catch`), экранға қызыл хабар етіп шығарады. Сайт ешқашан «қатып» қалмауы керек.
- Сандық өрістер: бос, теріс немесе сан емес мәнге тексеру.
